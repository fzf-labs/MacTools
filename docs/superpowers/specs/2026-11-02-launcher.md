# Native launcher

## Product contract

The launcher finds and opens existing capabilities. It has four result kinds: applications, macOS System Settings pages, host-owned macOS system operations, and enabled plugin features. It does not embed clipboard history, calculators, file search, quicklinks, or other business tools. Searching for Calculator opens the installed macOS app; searching for Clipboard opens the existing plugin window.

Option-Space toggles a fresh home. Home shows favorites and recently successful operations only; otherwise it offers a concise search prompt. Search supports normalized names, pinyin, initials, aliases, and fuzzy matching. Match quality precedes personalization. Results retain their stable selected identity when catalogs refresh. Every result names its kind and plugin-owned results identify their provider.

Applications can open/focus, reveal in Finder, and copy their paths. Additional folders or single app bundles can be included through Launcher Settings. Scans run off-main and observe directory changes. Finder and cryptex Safari locations are included without indexing nested helper apps.

The host discovers macOS settings pages from installed ExtensionKit metadata on a worker, using system-localized names, stable identities, and a shared cache. Navigation metadata, contextual-page policy, and public hardware metadata filter inappropriate entries. Unknown availability callbacks are not executed. Preserve the original twenty page IDs; use bundle IDs for newly discovered pages. Installed common pages remain the uncached fallback when discovery fails. Camera, microphone, screen recording, accessibility, full disk access, input monitoring, and automation receive explicit privacy subpage shortcuts when the parent pane exists. Execution revalidates the extension and hardware. Failed navigation reports the failure and offers System Settings home.

## Built-in system actions

System Actions must be usable without installing or enabling plugins. A fixed host catalog provides common Mac commands through the existing executor. System commands always use host-owned references and identities, with no plugin delegation or fallback. Plugin-owned entries remain in Plugin Features and are subject to plugin lifecycle. Search has no side effects. Session-ending and destructive commands require confirmation, and permissions or unsupported devices produce explicit feedback.

## Plugin boundary

Existing action definitions and canonical references remain the execution source of truth. The optional `PluginLauncherActionProviding` protocol declares discoverable plugin functionality or excludes it. Legacy system-operation hints from plugins are normalized to Plugin Features, preserving the published ABI. Reviewed official legacy mappings support existing binaries. Unknown providers default to excluded. No classification by localized title or ID substring is permitted.

Configuration, permissions setup, shortcut management, import/export, and internal actions are absent from normal results. Actual workspaces hosted in Settings remain valid feature destinations. An execution failure may provide an owner-settings recovery link. Disabled, removed, or isolated providers disappear immediately; stored preferences survive. Confirmation and execution use the existing executor, including a second validation before effects begin.

The launcher does not read the pasteboard or selected text on presentation. Text paste edits the search query. Input actions open the existing composer. There are no embedded tool pages, arbitrary script runtimes, content attachments, or launcher tool bundles.

## Settings and compatibility

Settings contains an expandable Launcher group alongside MacTools, Customize, and Plugin Settings with General, Applications, System Settings, System Actions, and Plugin Features as child pages. It manages shortcuts, application scopes, inclusion, favorites, aliases, hidden entries, and usage clearing. Inclusion never disables the provider or changes other shortcuts. Business settings remain with their plugins.

Keep the old command palette and shortcut independent; transient panels are mutually exclusive. Seed Option-Space once without replacing conflicts or restoring an explicitly cleared shortcut. Retain portable personalization through existing backups while keeping application paths, scopes, and usage local. Removed draft-tool preferences and plugin data are not deleted.

PluginKit additions retain ABI version 7 and require host 2.2.0 for consumers. Remove only the unpublished draft tool interfaces. Preserve the user's existing clipboard consolidation work, historical signed catalogs, and all original plugin interfaces.
